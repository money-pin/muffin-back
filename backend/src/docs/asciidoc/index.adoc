[[investment-settlement-result]]
== 정산 결과 팝업 조회 (INVEST-06)

가장 최근 정산 대상 투자의 결과를 조회한다. 정산 완료(SETTLED)면 손익 결과를 반환하고, 그 외에는 사유(`reason`)만 반환한다.

* `SETTLEMENT_PENDING`: 정산 배치가 아직 완료되지 않음(정산 중)
* `NO_INVESTMENT`: 최근 정산 대상 투자가 없음(미투자/취소 포함)

NOTE: 인증(`Authorization: Bearer {accessToken}`)이 필요하다. 사용자는 access token에서 해석하므로 별도 요청 파라미터가 없다. 인증 실패 시 `401 AUTH_401_001`을 반환한다.
FE 담당자는 invest_date를 로컬에 저장하여 같은 투자 결과 팝업을 1회만 보여줄 수 있도록 한다.

[[auth-login]]
== 로컬 로그인 (Auth-02)

이메일/비밀번호로 로그인하고 access token을 응답 바디로, refresh token을 HttpOnly Cookie(`refreshToken`, Path=`/api/auth`, Secure, SameSite=Strict)로 발급한다.

NOTE: 가입되지 않은 이메일과 비밀번호 불일치는 계정 존재 여부가 노출되지 않도록 동일한 에러(`AUTH_401_002`)로 응답한다.

NOTE: 비밀번호를 5회 연속 틀리면 계정이 30분간 잠긴다(`AUTH_423_002`). 잠긴 뒤에는 올바른 비밀번호를 넣어도 비교 자체를 하지 않고 즉시 거부하며, 30분이 지나면 별도 배치 없이 자동으로 해제되고 실패 횟수도 초기화된다. 잠기기 전에 로그인에 성공하면 그 시점에 실패 횟수가 즉시 초기화된다.

[[auth-token-refresh]]
== Access Token 재발급 (Auth-02)

요청 Cookie의 refresh token(`refreshToken`)으로 access token을 새로 발급한다. 요청 바디는 없고 `Authorization` 헤더도 필요 없다(만료된 access token을 대체하기 위한 API이므로).

NOTE: 재발급할 때마다 refresh token도 함께 회전(rotate)된다. 새 refresh token이 다시 `Set-Cookie`로 내려가고, 재발급에 쓰인 기존 refresh token은 그 즉시 무효화되어 재사용할 수 없다(탈취 재사용 방지).

[[auth-withdraw]]
== 회원 탈퇴 (Auth-09)

Authorization 헤더의 access token으로 식별된 계정을 탈퇴 처리한다. 이름은 즉시 삭제되고 이메일은 복구 불가능한 값으로 대체되며(원본 이메일의 해시만 별도 보관), refresh token이 무효화되고 refresh token Cookie가 만료(`Max-Age=0`)된다.

NOTE: 탈퇴한 이메일은 30일간 재가입이 제한된다(<<auth-signup>>). 투자/퀴즈 기록은 탈퇴 6개월 후 별도 배치가 삭제하며, 집계 통계는 비식별 상태로 영구 보관된다.

== 구글 로그인/가입 (Auth-02)

구글 Sign-In SDK가 발급한 ID Token을 검증해 기존 계정이면 로그인, 없으면 자동 가입한다(회원가입/로그인을 별도 엔드포인트로 나누지 않음). 구글 로그인 자체가 동의 절차를 거치므로 서비스 약관도 자동 동의로 간주하고, 구글이 이미 이메일을 검증했으므로 가입 시 `Auth.emailVerified`가 곧바로 `true`로 시작한다.

NOTE: ID Token은 서명(JWKS), 발급자(`iss`), 대상(`aud`)을 모두 검증한 뒤 `sub`(구글 계정 고유 ID)로 기존 가입 여부를 판단한다.

[[stats-summary]]
== 수익 통계 조회 (STATS-02)

가입 이후 누적 손익, 최근 7일 누적 수익률 그래프, 수익 TOP3 섹터, 투자 성향을 한 번에 조회한다. 정산 완료(SETTLED)된 투자만 집계한다.

* 누적 수익률: 초기자본 100만원 기준(`누적 손익금 / 1,000,000 × 100`), 소수 첫째자리.
* 그래프: 가장 최근 정산일을 포함한 직전 7일. 각 날짜는 그 날까지의 누적 수익률이며, 투자하지 않은 날은 직전 누적을 그대로 유지한다(손실 시 음수).
* TOP3 섹터: 섹터 누적 수익률(그 섹터 누적 매수금 기준) 내림차순 3개.
* 투자 성향: 섹터 그룹별 누적 매수 비중으로 판정(STABLE/BALANCED/GROWTH/AGGRESSIVE).

NOTE: 인증(`Authorization: Bearer {accessToken}`)이 필요하다. 사용자는 access token에서 해석하므로 별도 요청 파라미터가 없다. 인증 실패 시 `401 AUTH_401_001`을 반환한다.

[[stats-history]]
== 누적 수익 내역 조회 (STATS-08)

기간 탭(일/주/월/년/전체) 단위로 그 기간에 발생한 누적 손익을 요약하고, 종목(섹터)별 내역을 원하는 기준으로 정렬해 조회한다. 정산 완료(SETTLED)된 투자만 집계한다.

* 요약 손익률: 그 기간 누적 매수금 기준(`기간 손익금 / 기간 매수금 × 100`), 소수 첫째자리. 매수 이력이 없으면 0.0.
* 종목(섹터) 손익률: 그 섹터의 기간 누적 매수금 기준, 소수 첫째자리.
* `hasPrev`/`hasNext`: 선택한 기간 윈도우 밖(이전/이후)에 정산 완료 데이터가 있는지로 판단한다. 좌우 화살표 네비게이션 활성화에 쓴다.
* `date`: `period` 형식에 맞춰 지정한다(DAY=`YYYY-MM-DD`, WEEK=`YYYY-Www`(ISO 주차), MONTH=`YYYY-MM`, YEAR=`YYYY`, ALL=불필요). 미지정 시 해당 `period`의 현재(오늘/이번 주/이번 달/올해, KST)로 처리한다. `period=ALL`이면 응답에서 `date`가 생략된다.

NOTE: 인증은 `Authorization: Bearer {accessToken}`로 처리하며, 사용자는 토큰에서 해석한다. 인증 실패 시 `401 AUTH_401_001`을 반환한다.

[[stats-recent-detail]]
== 최근 투자 성과 상세 (STATS-03)

가장 최근 정산 완료(SETTLED)된 투자 1건을 섹터별로 상세하게 조회한다. 최근 투자 결과 화면에서 섹터별 손익을 확인하는 데 쓴다.

* `date`: 조회된 최근 정산 완료 투자의 일자(KST). 정산 이력이 없으면 `null`이다.
* `totalInvestment`/`profitAmount`: 그 투자의 총 매수금과 총 손익금(손실 시 음수).
* 섹터 손익률(`sectors[].profitRate`): 그 섹터 매수금 기준(`섹터 손익금 / 섹터 매수금 × 100`), 소수 첫째자리. 매수금이 0이면 0.0.
* `sectors[].isFallback`: 거래정지 등으로 시가를 확보하지 못해 0%가 적용된(폴백) 섹터면 `true`. 이 경우 손익금/손익률은 0이다.
* 섹터는 매수금(`totalInvestment`) 내림차순으로 정렬된다.

NOTE: 인증(`Authorization: Bearer {accessToken}`)이 필요하다. 사용자는 access token에서 해석하므로 별도 요청 파라미터가 없다. 인증 실패 시 `401 AUTH_401_001`을 반환한다.

NOTE: 인증(`Authorization: Bearer {accessToken}`)이 필요하다. 사용자는 access token에서 해석하므로 별도 요청 파라미터가 없다.

* 정렬은 열람 시각 내림차순 하나뿐이라 `sort` 파라미터가 없다.
* `cursor`/`size`(1~50, 기본 10): 커서 페이지네이션. `nextCursor`는 다음 페이지가 있을 때만 내려간다(없으면 응답에서 생략).
* 응답 필드는 스크랩 목록과 동일하게 camelCase로 통일했다(`newsId`/`categoryName`/`thumbnailUrl`/`viewCount`/`publishedAt`/`viewedAt`/`nextCursor`/`hasNext`). `category`는 코드가 없어 표시명(`categoryName`)으로 내린다. 시각은 KST 오프셋(`+09:00`)을 포함한다.
